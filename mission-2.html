공통 미션을 내 분야로 한 번 더

1·2차시에 함께 만든 우리 모임 운영 서비스의 구조를 그대로 빌려, 내 일이나 관심사에 맞는 웹앱을 만들어 봅니다. 기술은 이미 배웠어요. 바뀌는 건 주제와 내용입니다.

미션 1 · 1차시 응용질문 → 점수 → 결과 구조로 내 분야 진단·퀴즈 만들기
예: 정리 유형 진단, 상품 등록 준비도 진단, 아이 구구단 퀴즈
미션 2 · 2차시 응용소개 + 목록 등록·수정·삭제·저장 구조로 내 분야 관리 앱 만들기
예: 강의 일정 관리, 상품 등록 일정, 추천 장소 목록

미션 1 · 1차시 응용

내 분야 진단·퀴즈 만들기

성향 테스트(질문 5개 → 보기별 점수 → 결과 유형)와 같은 구조로 만듭니다. 고르고 채우면 아래 단계별 프롬프트가 바뀌어요. 노란 글씨가 내가 고르거나 쓴 내용이에요.

모임 소개 + 일정 등록·수정·삭제·저장 구조를 내 분야에 맞게 바꿉니다. 목록에 넣을 항목을 직접 정할 수 있어요.

1내 말로 먼저 적기

2고르고 채우기

사용항목 이름필수종류
숫자 항목은 "0 이상 모든 정수"로 요청돼요. 2차시에 AI가 1000원 단위 제한을 몰래 넣었던 일을 막기 위해서예요.

3단계별 프롬프트

링크로 함께 보는 앱은 링크를 가진 누구나 데이터를 보고 고칠 수 있어요. 연습용 데이터만 넣으세요.

개발 경험자 트랙

내 작품을 프롬프트로 설계하기

코드를 바로 받지 않고 기획서 → 구현 계획 → 단계 구현 → 코드 리뷰 순서로 갑니다. 이미 Codex나 다른 도구를 쓰고 있다면, 여기서 만든 기획서를 그 도구에 그대로 넘겨도 돼요.

키가 필요한 API의 키를 HTML에 넣으면 누구나 볼 수 있어요. 공개할 서비스라면 키는 서버 쪽에 두는 구조가 필요하고, Canvas에서는 데이터베이스 보안 규칙을 직접 정하기 어렵다는 점도 기획서에서 함께 검토하세요.
FINAL CHECK

마무리 · 교차검증과 공유

어떤 트랙이든 마지막은 같아요. AI에게 먼저 문제를 찾게 하고, 확인된 것만 고친 뒤, 직접 다시 눌러 봅니다.

지금까지 만든 웹앱의 전체 코드를 검토해 주세요. 1. 최초 요구사항과 현재 기능을 비교해 주세요. 2. 기존 기능 누락, 입력값 검사, 등록·수정·삭제 오류를 확인해 주세요. 3. 숫자 입력에 요청하지 않은 단위 제한(예: 1000원 단위)이 있는지 확인해 주세요. 4. 사용자 입력이 HTML로 실행되지 않도록 안전하게 표시되는지 확인해 주세요. 5. 저장 상태, 새로고침, 다른 기기에서의 반영을 점검해 주세요. 6. 화면에서의 권한 제한과 실제 데이터베이스 보안을 혼동하지 마세요. 7. 코드만 검토한 부분과 실제 실행 테스트 결과를 구분해 주세요. 발견한 문제를 중요도순으로 정리하되 아직 코드는 수정하지 마세요.

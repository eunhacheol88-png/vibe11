왜 프롬프트가 이렇게 길어졌을까요

오늘 프롬프트는 강사가 미리 여러 번 돌려 보면서, 오류가 날 때마다 한 줄씩 더해 만든 거예요. 처음부터 이렇게 쓸 수 있는 사람은 없어요. 그래서 우리는 메타 프롬프트로 받아서 씁니다.

2알아야 할 핵심 개념

공용 게시판과 내 수첩공용 저장소에 붙이면 모두가 보고 새로고침해도 남아요. 이 창 메모리에만 적으면 나만 보이고 새로고침하면 사라져요.
연결 상태 표시보이지 않던 문제를 눈에 보이게 해서, 다음에 또 끊겨도 바로 알 수 있게 해요.

3제미나이에 보낼 프롬프트

먼저 확인해요 ① Canvas 오른쪽 위 공유로 링크 복사 ② 일반 창(내 계정)과 시크릿 창(두 번째 계정)에 열기 ③ 한쪽에서 일정 등록 후 다른 쪽에 새로고침 없이 보이는지, 새로고침해도 남는지 보기

지난 시간에 만든 일정 저장과 실시간 공유를 점검하고, 안 되는 부분이 있으면 고쳐 주세요. 이런 문제가 있는지 확인해 주세요 - 일정을 등록해도 같은 공유 링크를 연 다른 창에는 보이지 않음 - 등록한 창에서 새로고침하면 일정이 사라짐 원하는 동작 1. 일정 등록, 수정, 삭제는 모두 Canvas가 제공하는 Firebase 데이터베이스의 공용 경로(모든 사용자가 함께 쓰는 곳)에 저장해 주세요 2. 실시간 리스너로 같은 공유 링크를 연 모든 창에 새로고침 없이 바로 보이게 해 주세요 3. 새로고침해도 일정이 그대로 남아 있게 해 주세요 4. 일정 목록 위에 저장소 연결 상태를 보여 주세요. 연결되면 '🟢 공용 저장소 연결됨', 연결되지 않으면 '🔴 저장소 연결 안 됨' 5. 저장소에 연결되지 않았을 때 몰래 이 창에만 저장하지 말고, 등록 버튼을 누르면 '저장소에 연결되지 않아 저장할 수 없어요'라고 알려 주세요 6. 이미 실시간 공유가 잘되고 있다면 저장 방식은 바꾸지 말고 4번과 5번만 추가해 주세요 7. 화면 위 '2차시 진행 중' 표시를 '3차시 진행 중'으로 바꿔 주세요 지켜 주세요 - 메뉴 순서(성향 테스트, 모임 소개, 회비 정산, 외출 지수)와 메뉴 이름을 바꾸지 마세요 - 성향 테스트, 모임 소개 내용, 일정 입력 칸, 디자인은 그대로 두고 저장과 실시간 반영 부분만 고쳐 주세요 - 처음부터 다시 만들지 마세요 고친 뒤 무엇이 문제였는지 생활 속 비유 하나로 3줄 이내로 설명하고, 제가 두 창으로 확인하는 방법을 알려 주세요. Canvas 미리보기로 바로 실행되게 보여 주세요.

방금 설명을 프로그래밍을 모르는 사람도 알 수 있게 다시 설명해 주세요. 영어 용어와 코드 이름은 쓰지 말고, 생활 속 비유 하나로 3줄 이내로 써 주세요. 그리고 제가 화면에서 직접 확인하는 방법을 알려 주세요.

2알아야 할 핵심 개념

3제미나이에 보낼 프롬프트

저장한 HTML 파일을 첨부하고, 대괄호 두 곳을 지금 상황에 맞게 바꿔서 보내세요.

첨부한 HTML은 제가 제미나이 캔버스로 만들고 있는 '우리 모임 운영 서비스'입니다. 대화가 길어져서 새 채팅에서 이어서 작업합니다. 당신의 역할: 이 앱을 이어서 고쳐 주는 개발 도우미 앱의 목적: 모임 일정을 함께 등록하고, 참여 신청을 받고, 회비를 정산하는 웹앱 (여러 사람이 같은 링크로 실시간 사용) 지금까지 된 것: [예: 0~5단계 실시간 저장, 내 일정 권한, 참여 신청, 회비 계산, 참석 명단] 다음에 할 것: [예: 6단계 정산 상태] 작업 규칙 1. 먼저 첨부한 코드를 Canvas로 열어, 코드는 한 글자도 바꾸지 말고 그대로 실행되게만 보여 주세요 2. 열고 나면 지금 있는 기능을 5줄 이내로 정리하고, 제 다음 요청을 기다려 주세요 3. 앞으로 고칠 때는 필요한 부분만 고치고, 기존 코드를 생략하거나 잘라 내지 마세요 4. 메뉴 4개(성향 테스트, 모임 소개, 회비 정산, 외출 지수)의 순서, 위치, 디자인은 바꾸지 마세요 5. 매번 Canvas 미리보기로 바로 실행되게 보여 주세요
새 채팅에서는 공유 링크가 새로 생겨서 일정 목록이 비어 있을 수 있어요. 새로 공유한 링크로 일정을 하나 등록하고, 두 번째 계정으로 참여 신청까지 해 두면 다음 단계 시험이 편해요.

6-1 정산 상태

회비 정산에 '정산 중'과 '정산 완료' 상태를 추가하려고 합니다. 필요한 부분만 고치고, 나머지 코드는 한 줄도 바꾸지 마세요. 고쳐도 되는 곳은 두 군데뿐이에요 - 회비 정산 화면 맨 아래 정산 확정 버튼이 있는 영역 - 모임 소개 일정 카드의 정산 표시 줄 할 일 1. 정산 확정을 하면 상태를 '정산 중'으로 저장해 주세요 (지금처럼) 2. 정산 중이면 일정 담당자에게 정산 확정 버튼 아래 '입금 완료 처리' 버튼을 보여 주세요. 누르면 상태를 '정산 완료'로 저장해 주세요 3. 정산 완료면 일정 담당자에게 정산 확정 버튼과 입금 완료 처리 버튼을 숨기고 '정산 중으로 되돌리기' 버튼만 보여 주세요. 누르면 다시 '정산 중'이 돼요 4. 정산 완료면 참석 명단 체크박스와 참석자 추가 칸을 잠가 주세요 5. 버튼을 누른 직후 일정을 다시 고르지 않아도 버튼과 상태가 바로 바뀌게 해 주세요 6. 일정 카드의 정산 표시는 정산 중이면 노란색, 정산 완료면 초록색으로 보여 주세요. 금액 표시(총비용, 인원, 1인당)는 그대로 두세요 바꾸면 안 되는 것 - 메뉴 4개의 순서, 위치, 디자인 - 성향 테스트, 모임 소개, 일정 등록 폼, 일정 카드의 배치와 디자인 - 회비 정산 화면의 배치와 디자인 - 금액이나 인원을 바꾸면 1인당 회비, 총 걷히는 금액, 더 걷히는 금액이 바로 계산되어 보이는 기능 - 참석 명단, 불참 표시, 현장 추가, 참여 신청, 실시간 저장 작업 방식 - 처음부터 다시 만들지 말고, 기존 코드를 생략하거나 잘라 내지 마세요 - 고친 뒤 어느 부분을 바꿨는지 3줄 이내로 알려 주세요 Canvas 미리보기로 바로 실행되게 보여 주세요.

6-2 참여 마감 (6-1 확인 후)

정산이 시작된 일정은 참여 신청을 마감하려고 합니다. 필요한 부분만 고치고, 나머지 코드는 한 줄도 바꾸지 마세요. 고쳐도 되는 곳은 한 군데뿐이에요 - 모임 소개 일정 카드의 참여하기, 참여 취소 버튼이 있는 영역 할 일 1. 일정의 정산 상태가 '정산 중'이나 '정산 완료'이면 참여하기와 참여 취소 버튼을 숨기고, 그 자리에 '참여 신청이 마감됐어요'라고 보여 주세요 2. 정산 상태가 없는 일정은 지금처럼 참여하기와 참여 취소가 그대로 되게 해 주세요 3. 정산 상태는 카드를 그리는 그 자리에서 그 일정의 정산 정보를 직접 읽어서 확인해 주세요. 새로 쓰는 이름(변수)은 쓰기 전에 반드시 먼저 만들어 두세요 4. 상태가 바뀌면 다른 창에도 실시간으로 반영되게 해 주세요 바꾸면 안 되는 것 - 메뉴 4개의 순서, 위치, 디자인 - 일정 등록, 일정 카드의 다른 부분과 배치, 디자인 - 회비 정산 화면 전체 (계산, 버튼, 상태) - 참석 명단, 불참 표시, 현장 추가, 실시간 저장 작업 방식 - 처음부터 다시 만들지 말고, 기존 코드를 생략하거나 잘라 내지 마세요 - 고친 뒤 어느 부분을 바꿨는지 3줄 이내로 알려 주세요 Canvas 미리보기로 바로 실행되게 보여 주세요.
